## 第四阶段：Three.js 3D 场景还原（已完成，headed 浏览器验证零错误）

- **核心方法**：从 `extracted/js/_nuxt/gpNsPhdA.js`（2.2MB 压缩原站包）逆向出全部装配参数，不靠猜。
- **关键真值**：
  - `RENDERER_CONFIG={powerPreference:'high-performance',antialias:false,stencil:false,alpha:false,depth:true}`；`SCENE_BACKGROUND_COLOR=197379`(#030303)；`outputColorSpace=srgb`；`pixelRatio=min(2,dpr)`。
  - `cameraViews.HomeDesktop = pos(-1.5,0.5,3) / lookAt(0,0.7,0) / fov 55 / far 150`。`state_v9` 里 `Camera/Views/HomeDesktop` 的 (-15.5,1.5,0) fov73 **不可用**（相机在沙丘内部，且其轨道数据为空）。
  - 相机是 **bike group 的子约束对象**（`cameraConstraintPosition/LookAt`），不是绝对坐标 → 必须 `bike.add(anchor)` 每帧 `getWorldPosition`。
  - `worldConfig.RADIUS=120`、`bikeConfig.INITIAL_PHI=5.92023817104828` → bike 在 `(112.2, 0, -42.6)`，朝向切线；该处地面高度实测 **0.006**，与 y=0 吻合（说明这是对的摆放）。
  - `lightsConfig={intensity:3, direction:(-0.4,1,-0.5)}` + `state_v9.World.sun` 色 (0.867,0.804,0.545)。**intensity 3 是给自定义 Toon shader 的**，套 PBR 会全白过曝 → 按 PBR 重标定 2.6（+hemi 0.5 + ambient 0.28）。
- **材料真值**（`state_v9.sheetsById.bike.staticOverrides.byObject`）：front_mudguard/lining `#2e4035` 墨绿、fairing `#cbc8c1` 米白、seat `#1f1f21`、horn `#7e6842`、tire `#2b2c2d`、motor/rear_rim `#999283`。按 mesh 名把 material clone 后设 color（材质共享必须 clone）。
- **地面**：GLB 自带 `sol.001` 贴图只是遮罩（渲成黑白斑驳）。原站用 `MeshBlendRampNoiseToonMaterial`，主色是 `map_ground_v2.1.webp`（预烘焙沙色+阴影）。本实现换成 `MeshStandardMaterial({map: map_ground_v2.1})` + onBeforeCompile 混 R/G/B 细节（G_sand/B_marble/R_rock + blendmap，repeat 80）。
- **天空**：`skybox-day.jpg` 是 **50×1600 的垂直渐变条**（非 equirect），原站用 `createRenderTargetShader` 拉伸。本实现用内翻球体 + 竖向渐变 shader。**坑：球半径 900 必须把 camera.far 从 150 提到 1200，否则整个天幕被裁剪变黑。**
- **鸟群**：原站拿 oiseau geometry 做 GPU 粒子（`MeshToonMaterial` + 属性 age/size/uv_offset）；本阶段克隆 9 只静态摆放。
- **必须修的两个模型坑**：
  1. `tree_chain_02_instance_forest` / `tree_chain_instance_forest` 是 InstancedMesh 且 geometry 有 morphAttributes，但 GLTFLoader 没初始化 `morphTargetInfluences` → three r187 在 `WebGLMorphtargets.update` 读 `.length` 崩（`Cannot read properties of undefined`）。运行时补 `new Array(count).fill(0)`。（原站旧版 three 是把这些设成 undefined，新版不能。）
  2. `obstacle_0~3` 是 game 模式障碍物，home 模式必须隐藏，否则挡在相机前。
- **Nuxt 4 大坑**：`.client.vue` 组件在 Suspense 下，`onMounted` 触发时 **template ref 还是 null**（DOM 后插入）。用 `watch(ref, fn, {flush:'post'})` 初始化；`getElementById` 同样拿不到。
- **环境**：无 GPU 的 headless Chrome（SwiftShader）跑该场景会 `WebGL context lost`（187 draw call / 163 万三角形超出软件渲染能力）。**验证 3D 必须用 `agent-browser --headed`**。已加 contextlost 暂停 + contextrestored 恢复 + 渲染循环 try/catch（防止单帧异常冒泡导致整页白屏）。
- **验收数据**：contextLost=false、187 draw calls、1,633,902 triangles、65 textures、28 programs、131 scene meshes、9 birds、skyDome ok、ground map ok、控制台零 error/warning。
- **构建**：`npm run build` 需先清 `node_modules/.cache/nuxt` 与 `.output`（safe-delete 50 文件限制），之后 5.87s 通过。
- **调试入口**：`window.__mola3d.getDebugInfo()` / `.getGroundHeightAt(x,z)` / `.applyCodeDefaultHomeView()`。

## 第五阶段：动画与交互（Theatre.js 轨道驱动）

### 核心发现（逆向 gpNsPhdA.js）
- `state_v9.json` 是标准 Theatre.js project state（definitionVersion 0.4.0），
  `@theatre/core@0.7.2` 可直接 `getProject(name,{state})` 消费，无需转换。
  验证：`HomeDesktop` t=0 读出 (-1.102,0.6,1.8)/(0.1,0.4,0.2)/fov 91/far 200。
- **整条动画由 bike 的 phi 驱动**：
  `sequence.position = ((2π - phi mod 2π) + 2π) mod 2π × 10 / 2π`
  （原站 SequenceBundle.updateCameraSequence）
- 首页 phi = `INITIAL_PHI 5.92023817104828`（沙漠区）→ position ≈ 0.578。
  **不能取 2π**——那是轨道另一侧宫殿区（大理石地面）。
- 运动模型：wheel speed += -deltaY*5e-5；drag speed += dx*5e-7；
  均 clamp ±0.01；每帧 speed*=0.95、targetPhi += speed*dt*40、
  phi = lerp(phi, targetPhi, 0.1)；|speed|<5e-4 时停。
- 车轮 `rotation.x += speed/(0.323377*2π)`，wobble `cos(t*50)*(0.0012+|speed|*0.1)`。

## 修复：宫殿区「地面全黑、空荡荡」（Zone Visibility 默认值）

### 现象
用户截图：宫殿柱廊里柱子/雕像在，但地面大片纯黑 (2,2,2)、左侧墙面与背景拱窗缺失。
原站同机位：完整浅灰石板地面 + 柱影 + 拱窗。

### 根因
`app/utils/mola3d/theatre.ts` 的 ZONE_VISIBILITY_PROPS 把 11 个键全设 false。
原站 SequenceBundle.create$4：
```js
objects = ["zone_0","zone_0_1","zone_1","zone_1_2","zone_2","zone_2_3","zone_3",
           "palace_inner","palace_outer","shop","birds"]
          .map(n => getScene().getObjectByName(n)).filter(Boolean)
props = objects.reduce((o,g) => (o[g.name] = types.boolean(g.visible), o), {})
```
**默认值取 GLB 节点自身 visible，不是 false**。
GLB 层级：`palace_ground / palace_wall / palace_roof -> palace_outer -> zone_2`；
`pillar_palace -> palace_inner -> zone_2`。
`palace_outer` 无关键帧 → 被我们永久 false → 地面/墙/屋顶消失，
`palace_inner` 有关键帧 → 柱子仍在，正好对应用户截图。
另：原站键列表含 `shop`、不含 `flare`，之前写反了。

### 修复
- theatre.ts：ZONE_KEYS 改为原站 11 键，删掉全 false 的 ZONE_VISIBILITY_PROPS
- sceneManager.ts：applyZoneVisibility 记录各 zone 的 GLB 初始 visible 到
  zoneInitialVisible；initOrbitalSequence 用它构造 sheet.object props；
  applyZoneTrackValues 对非 boolean 值跳过（保持 GLB 原状）
- 实测首页 zone：zone_0/0_1/3 true，zone_1/1_2/2/palace_inner false，
  zone_2_3/palace_outer/shop true（无关键帧 → GLB 默认），首页无回归

### 验证
- 地面近 (2,2,2) → (153,135,117)；原站 (129,114,101)
- 三个宫殿机位 phi=1.9/1.6/1.3 全部恢复完整石板地面、拱窗、穹顶、雕像

### 剩余偏差（已定位，未做）
偏亮约 20 且缺斜向柱影 = 原站 USE_STATIC_SHADOW 未移植。
原站用两盏 4096² DirectionalLight 运行时烘焙 staticShadowMap /

## 修复：宫殿柱子泛紫（配色表缺失导致回落默认紫）

### 现象
用户截图：宫殿柱身整根泛蓝紫，柱基上一块规整淡紫矩形。
用户图紫块像素 (152,148,165)；原站同位置 (153,149,166) —— 两站都有，
但原站只在小块 UV 空白区露紫，我们整根柱身背光面都吃满紫。

### 根因（实验确认）
- GLB 里柱廊是 4 个 EXT_mesh_gpu_instancing 网格：
  `constraint_allé_pilonne0/1` (map=pillar_1024px)、
  `2` (socle_02_v1.1_optimized)、`3` (statue_02_v2 3-min)。
- 这 4 个名字**不在 toon-colors.json 的 119 条配色里** →
  回落 `DEFAULT_PALETTE`：`d #dab79c / i #605d87`（蓝紫）。
- Toon 公式 `贴图 × (direct·toonIrr + indirect·(1-toonIrr))`，
  背光面吃满 #605d87；`pillar_1024px` 是白底黑线描 atlas，
  UV 未覆盖区露出 Toon 底色 → 规整淡紫矩形。
- 判别实验：把柱子 map 设 null → 柱身整根纯淡紫（证明紫来自材质底色，
  不是贴图）；全局把 uIndirectColor 改暖 → 粉紫味消失。

### 修复（已落盘）
- `sceneManager.ts`：新增 `PILLAR_FALLBACK_PALETTE`
  （d 保持默认 #dab79c 不变，仅 i 改暖灰棕 [0.6,0.54,0.46]，
  nd/ni 同值）；类字段 `pillarWarm = true`；
  `applyWorldToonMaterials` 对 `/pilonne|pillar/i` 且未命中色板的网格用它；
  missing 警告排除这 4 个（40 → 36 条）。
- `MolaScene3D.client.vue`：`?pillarPalette=default` 可还原原站默认紫。
- `bikeAnimation.ts`：dispose() 去掉 `uncacheRoot()`——
  three 对已清空动作表再次 _removeInactiveAction 会抛
  "Cannot set properties of undefined (setting '_cacheIndex')"（HMR 时必现）。

### 严格对照验证（同机位，地面 151,133,116 vs 150,132,115 证明机位一致）
- 柱身：去紫 (188,178,165) / 原紫 (153,148,166)
- 柱基：去紫 (211,197,183) / 原紫 (180,171,179)；原站柱身白区 (215,199,188)
- 4 个柱体网格命中新配色；鸟群 20、人物动画在、首页 phi=5.92；
  稳定加载后控制台无 error（文件刚改完的 HMR 瞬间仍可能报 _cacheIndex）。

### 边界
按用户要求**未改动宫殿 zone 互斥逻辑**。
`mask_palace*` 的隐藏代码当前在源码里是被注释状态（用户自行调整），未动。

## 第六阶段补充：游戏模式对齐原站 + 雾/尘埃/环境氛围

**游戏模式（app/utils/mola3d/gameMode.ts）**
- 关键修复：`lastObstaclePhi` 初值必须是 `bikeConfig.INITIAL_PHI`(5.9202)，不是 `gamePhi`。
  写成 gamePhi 会让第一个障碍延迟 0.125rad（≈3.5s），画面像「空无一物」。
- `generateObstacleTick` 原站是每帧调用（靠 OBSTACLE_MIN_INTERVAL 限距），不要按 1/12s 限频。
- 车道导引弧 `initGameHelperCurve`：4 条 R±1/±3、y=0.1、白色 opacity .06 的弧（arc=2π*0.15），
  用极薄 RingGeometry 代替 MeshLine（点约定 (cosθ, 0, -sinθ)，`rotation.x=-π/2`），
  整个 group 每帧 `rotation.y = -phi`。这是「游戏里有路」的观感来源。
- 障碍挂在 decorGroup 下（原站 animate instancedObject.position.y -3→0 / 0→-3）。
- 换道补间：车横向 `(col-1)*-2`，相机 `columnOffset=2-2*col`，时长 `0.7/max(1,speed/INITIAL*0.15)`，
  keyPressed 锁 300/同系数 ms。相机偏移也要补间（原站 animate(cameraState,...)），否则瞬跳。
- 碰撞盒是 (1,1,1)（不是 1.4）。
- 死亡面板文案对齐 i18n：`Nice one! Try again` + Best score/Your score + Restart/Quit。
- 障碍材质直接复用原型 Toon 材质；原站 OBSTACLE_MOEBIUS_CONFIG 的键带 `_v11` 与 GLB 节点名
  (`cactus_02_reference`) 不匹配，等价于用 DEFAULT_PALETTE —— 这是「原站就这样」，不要乱调。

**雾（toonMaterial.ts + sceneManager）**
- 原站 FogBundle 是自定义噪波指数雾：手写 defines.USE_FOG/FOG_EXP2，替换 4 个 fog chunk，
  雾色固定 #550000，`fogDensity = Fog/intensity * 0.02`，`fogTime += dt*0.01`。
- 已完整移植（applyFog / setFogIntensity / tickFog），并同时驱动 `Fog/thichness` → 描边 uThickness。
- 注意 chunk 顺序：r177 与 r187 都是 fog 在 colorspace 之后，数学一致。

**扬尘（dust.ts）**
- 原站 initBikeParticles：400 粒子、dust.png、rate = speed*2.6*rateFactor*200（<50→0）、
  lifetime .4、size 1→11→0、挂 bike root 的 z=0.9。用 Points + 自定义 shader 复刻。
- `Dust` 轨道要 `types.rgba` 绑定 color，否则颜色不会跟轨道变。

**开发工具**
- `scripts/dev-browser.mjs <scenario.mjs>`：无头 Chrome + CDP（ws），
  scenario 导出 `({page, wait, shot, log})`，page.eval 注入代码、shot 存 analysis/screenshots。
  用于逐项回归（`analysis/scenario-game.mjs` / `scenario-fog.mjs` / `scenario-dust.mjs`）。
